# ADR-002: Backend em Python/FastAPI e frontend em React desacoplado via REST

## Status
Accepted

## Contexto
O núcleo do sistema são as regras do xadrez (geração de lances legais, detecção de estados), que precisam ser legíveis, testáveis e fáceis de evoluir. O frontend precisa renderizar um tabuleiro interativo de forma ágil. A disciplina também exige documentar formalmente uma API (seção de Design de API), o que pede uma fronteira clara entre cliente e servidor. Cogitou-se usar um framework full-stack único, mas isso obscureceria a separação entre API e cliente que o trabalho precisa evidenciar.

## Decisão
O backend será escrito em **Python com FastAPI**, expondo uma **API REST**. O frontend será uma aplicação **React com TypeScript** (Vite) que consome essa API. As duas camadas se comunicam exclusivamente por HTTP/JSON.

## Consequências
- **(+)** O FastAPI gera a especificação **OpenAPI automaticamente**, atendendo a seção de Design de API com baixo custo.
- **(+)** A fronteira API/cliente fica explícita, facilitando a documentação e os diagramas de sequência.
- **(+)** Python favorece a legibilidade e a testabilidade do domínio; React acelera a construção da interface.
- **(−)** Exige manter dois ambientes (Node para o frontend, Python para o backend) e cuidar da serialização entre as duas pontas.
